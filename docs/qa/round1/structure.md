- **`width="auto"` / `height="auto"`** → `reps.go` — add non-auto concrete values for `width`/`height` when emitted on a child `<svg>` context, or fix `blueprint.go` to add a `viewBox` to the inner SVG body so `auto` doesn't collapse it.

**Card count:** 58  
**Visible:** 57  
**Empty/invisible cards:** 0 (all cards show the child rect)

### Problem cards (IDENTICAL_NO_EFFECT / GRAMMAR_ISSUE)

| Label | Issue |
|---|---|
| `fill="none"` | `<g fill="none"><rect fill="#4d8bff"/></g>` — the child rect has an explicit `fill` that overrides the group's `fill="none"`. Group attribute has no visible effect. |
| `requiredExtensions="label"` | Attribute is non-functional on `<g>` in SVG2; the child rect renders unconditionally. |
| `systemLanguage="label"` | Same — no conditional-rendering effect on `<g>`. |
| `role="main marqueemath"` | **GRAMMAR_ISSUE:** `RoleValue = RoleToken , { RoleToken }` concatenates tokens without a space separator → `"main marqueemath"` instead of `"main marquee"` or `"main math"`. |

### Fix targets

- **`role` value grammar** → `lang/svg.ebnf`: Change `RoleValue = RoleToken , { RoleToken }` to `RoleValue = RoleToken , { " " , RoleToken }` (add a space literal inside the repetition). This fixes the concatenation issue for all elements that have `role`. Affects `g`, `switch`, `a`, `symbol`, `unknown`, and all other elements.
- **`fill="none"` IDENTICAL_NO_EFFECT** → `blueprint.go` `bodyFor("g")`: Change the child rect to omit an explicit `fill` so the group's `fill` attribute is visible: `<rect x="20" y="20" width="60" height="60"/>` (inherits from group). This makes `fill="none"` produce a blank rect, `color="#e94560"` cascade visibly, etc.

## `<defs>` — HAS_EMPTY_CARDS (all 58 cards empty)

**Card count:** 58  
**Visible:** 0  
**Empty cards:** ALL 58

### Root cause

The template blueprint (`chrome-testing/html/template/defs.html`) places `{{ELEMENT}}` inside `<defs>` and references it via `<use href="#slot" x="10" y="10"/>`. However, the generated `<defs>` element receives an `id` from the attribute being varied (`id="circle1"`, `id="grad-a"`, etc.) — never `"slot"`. The `blueprintSlotNeedsID()` function returns `false` for `defs` (category is `catSelf`), so `ensureSlotID` is never called, and `<use href="#slot">` finds no matching element.

Additionally, a `<defs>` element itself is invisible by design — it is a container for reusable definitions. The only way to show its effect is via a child/referencing element, which the use-href mechanism is attempting but failing at.

### Problem cards (ALL)

All 58 cards: the `<use href="#slot">` resolves to nothing because the injected `<defs>` element's `id` is never `"slot"`.

### Fix targets

1. **`gallery.go` `blueprintSlotNeedsID`** → Add `case catSelf` handling specifically for `defs` and `symbol`: if the element's category is `catSelf` but the blueprint contains `href="#slot"`, the injected element needs `id="slot"`. Or more precisely:
   - Extend `blueprintSlotNeedsID` to return `true` for `defs` and `symbol` (the two `catSelf` elements with blueprints that reference `#slot`).
   - Alternatively, change the `defs` template blueprint to a self-contained scaffold that does not depend on `id="slot"`.

2. **`blueprint.go` (preferred)** → Change `defaultScaffold` / the `defs` template so the generated `<defs>` element's body is a gradient or clip that a sibling rect uses, with the defs always carrying `id="slot"`:
   ```
   <svg ...><defs id="slot">{{ELEMENT}}</defs><rect x="5" y="5" width="90" height="90" fill="url(#slot)"/></svg>
   ```
   But since defs is a container (not a paint server), the better fix is to put the visible child INSIDE defs' child (e.g. a `<clipPath>` inside `<defs>`) and demonstrate via the referencing rect.

3. **Simplest fix** → In `gallery.go`, extend `blueprintSlotNeedsID` to include `"defs"` and `"symbol"` so `ensureSlotID` is called and the injected element gets `id="slot"`, matching the `<use href="#slot">` in the blueprint.

## `<use>` — HAS_EMPTY_CARDS (74 of 75 cards empty)

**Card count:** 75  
**Visible:** 1 (the `href="#slot"` card)  
**Empty cards:** 74

### Root cause

The template blueprint (`chrome-testing/html/template/use.html`) defines:
```
<svg ...><defs><circle id="slot" r="12" fill="#e94560"/></defs>{{ELEMENT}}</svg>
```
The `baselineFor("use", ...)` in `blueprint.go` sets `href="#ref"` in the baseline. But the blueprint defines `id="slot"`, not `id="ref"`. So every generated `<use>` element has `href="#ref"` but no element with `id="ref"` exists in the DOM → 74 empty cards.

The single visible card (`href="#slot"`) works because the overlay forces `IriType` → `"#slot"`, then `NeedsID=true` adds `id="slot"` to the `<use>` element itself — coincidentally matching the `<circle id="slot">` in defs (the first `id="slot"` in DOM order wins).

### Fix targets

**`blueprint.go` `baselineFor("use", ...)`** → Change `href="#ref"` to `href="#slot"`:
```go
case "use":
    return add([2]string{"href", "#slot"}, [2]string{"x", "10"}, [2]string{"y", "10"}), false
```
This makes every non-href variant reference the circle defined in the blueprint's `<defs>`, so all 74 currently-empty cards will show the pink circle.

Alternatively, change the template blueprint to define `id="ref"` instead of `id="slot"` on the circle in defs, to match the baseline.

## `<switch>` — MOSTLY_PERFECT

**Card count:** 58  
**Visible:** all 58 show the child blue rect

### Problem cards (IDENTICAL_NO_EFFECT / GRAMMAR_ISSUE)

| Label | Issue |
|---|---|
| `systemLanguage="label"` | `"label"` is not a valid BCP47 tag. In SVG, `systemLanguage` on a `<switch>` element (not on a child) is not operative in SVG2. The child rect renders unconditionally. |
| `requiredExtensions="label"` | `"label"` is not a real extension URI. Browser suppresses the child only if the extension is unsatisfied — but since `requiredExtensions` on the switch container (not on children) is deprecated, the child renders. |
| `role="contentinfo definitiondeletion"` | **GRAMMAR_ISSUE:** Same as `<g>` — `RoleToken` concatenation without spaces: `"definitiondeletion"` should be `"definition deletion"`. |
| `stroke-miterlimit="0"` | Value `0` is out of the valid range (must be ≥ 1.0 per SVG spec). Renders as if clamped. Not a blank card but a grammar validity issue. |

### Fix targets

- **`role` concatenation** → Same fix as `<g>`: `lang/svg.ebnf` `RoleValue` needs space between tokens.
- **`stroke-miterlimit="0"`** → `overlay.go` `isNonNegativeAttr`: Add `"stroke-miterlimit"` to the non-negative list with a floor of `1` (it must be ≥ 1). Currently `isNonNegativeAttr` covers `stroke-width` but not `stroke-miterlimit`. Add: `case "stroke-miterlimit": return "1", true` in `overlaySample`, or add `"stroke-miterlimit"` to `isNonNegativeAttr` with a dedicated check for minimum `1`.
- **`systemLanguage="label"`** → `reps.go` or `overlay.go`: For `systemLanguage`, use a real BCP47 value like `"en"` instead of `"label"`. The value currently comes from `StringType` reps; add a context override in `overlaySample` for `attrName == "systemlanguage"` → return a real language tag (e.g. the browser's locale, or `"en"`). This would also make the conditional-processing effect visible in `<switch>` children.

## `<unknown>` — HAS_EMPTY_CARDS (all 58 cards blank, by design)

**Card count:** 58  
**Visible:** 0  
**Empty cards:** ALL 58 (dark background only)

### Assessment

`<unknown>` is the SVG spec's meta-element for unknown/unrecognized elements. Browsers render it as invisible (unknown elements in SVG produce no paint). All 58 cards correctly show a dark empty canvas because the `<unknown>` element produces no visual output.

**This is CORRECT behavior** — the element is genuinely non-rendering. The gallery demonstrates the full attribute vocabulary of `<unknown>`, which is the same set as `<g>` (presentation attrs, event handlers, ARIA, etc.). The cards are intentionally empty.

### Potential UI improvement

The gallery currently shows 58 blank-looking dark cards for `<unknown>` with no indication to the reader that blank=correct. Consider adding a note in the gallery description (e.g. `<unknown> is the SVG fallback element; it intentionally produces no visual output`) so reviewers understand the blank cards are expected.

**Fix target:** `emit/gallery.go` (`emitPage`) — add a per-element annotation slot for non-rendering elements, or add a fixed note in the template HTML. Low priority.

## Cross-Cutting Issues Summary

### Issue 1: `blueprintSlotNeedsID` misses `defs` and `symbol` (CRITICAL)

**Affected:** `defs` (58 empty), `symbol` (88 empty)  
**Root cause:** `gallery.go` `blueprintSlotNeedsID` only returns `true` for paint-server/filter/clip/mask categories. `defs` and `symbol` use blueprints that reference `#slot` via `<use href="#slot">`, but their injected element never gets `id="slot"`.  
**Fix:** `chrome-testing/cmd/gen/gallery.go` — extend `blueprintSlotNeedsID`:
```go
func blueprintSlotNeedsID(blueprint, tag string) bool {
    switch category(tag) {
    case catGradient, catPattern, catMarker, catClip, catMask, catFilter:
        return true
    }
    // defs and symbol use blueprints with <use href="#slot"> but are catSelf
    if tag == "defs" || tag == "symbol" {
        return true
    }
    return false
}
```

### Issue 2: `baselineFor("use")` uses `href="#ref"` but blueprint defines `id="slot"` (CRITICAL)

**Affected:** `use` (74 of 75 empty)  
**Fix:** `chrome-testing/cmd/gen/blueprint.go` `baselineFor`:
```go
case "use":
    return add([2]string{"href", "#slot"}, [2]string{"x", "10"}, [2]string{"y", "10"}), false
```

### Issue 3: `RoleValue` grammar concatenates tokens without spaces (GRAMMAR)

**Affected:** `g`, `switch`, `a`, `symbol`, `unknown` — and all other elements with `role`  
**Observed values:** `"main marqueemath"`, `"contentinfo definitiondeletion"`, `"alert alertdialogapplication"`, `"meter navigationnone"`  
**Fix:** `lang/svg.ebnf`:
```
RoleValue = RoleToken , { " " , RoleToken } ;
```

### Issue 4: `stroke-miterlimit` minimum value not enforced (GRAMMAR)

**Affected:** `g`, `switch`, and any element with `stroke-miterlimit`  
**Observed:** `stroke-miterlimit="0"` (spec requires ≥ 1.0)  
**Fix:** `chrome-testing/cmd/gen/overlay.go` `overlaySample` — add special case:
```go
case an == "stroke-miterlimit":
    return "1", true
```

### Issue 5: `systemLanguage` uses non-BCP47 placeholder value (GRAMMAR)

**Affected:** `g`, `switch`, `a`, `symbol`, `defs`, `use`, and all conditional-rendering elements  
**Observed:** `systemLanguage="label"` — not a valid BCP47 language tag  
**Fix:** `chrome-testing/cmd/gen/overlay.go` — add BCP47 override for `systemLanguage`:
```go
case an == "systemlanguage":
    return "en", true
```
Using `"en"` (matching a common browser language) would also make the conditional branch satisfy in `<switch>` children, producing a visible visual demonstration of the attribute's purpose.

### Issue 6: `<svg>` x/y at 100% push content off-screen (MINOR)

**Affected:** `svg` gallery — 2 cards (`x="100%"`, `y="100%"`)  
**Fix:** `blueprint.go` defaultScaffold for `catSelf` svg — the self-rendering svg should use a blueprint that keeps the varied `x`/`y` within visible range, or the `reps.go` `CoordinateType` samples should not include `"100%"` for position context.
